# wisp v2 Grid web: UX proposals

**Status:** proposals only. No repo file was changed. Owner's direction: fewer options showing, progressive disclosure, everything still reachable.

**How it was checked.** I built `cargo build -p wisp-grid` at `88101e23`. I ran `wisp-grid dev --port 8391 --data /tmp/uxgrid-data --wisp target/debug/wisp` and seeded it the real way:
- dev sign-in as `ada`;
- two devices through `/api/device/code` → `/activate` → Allow, each added as a computer;
- a signed task share through `POST /api/shares`;
- one published-app row.

I opened the cloud wisp through `/go`. Screenshots were taken with playwright-core: Chrome and WebKit, at 1280 and 390, light and dark. WebKit can't resolve `*.localhost`, so it went through a loopback proxy.

**Files:**
- Today's screenshots: `/tmp/qa-keep/ux-grid/today/`
- Mocks: `/tmp/qa-keep/ux-grid/NN-*-{1280,390}-{light,dark}.png`. Each mock is the real page with the proposal injected into its DOM, using the Grid's own CSS variables.

**What the paths look like today.**
- **Home:** 4 sections and about 18 controls.
  - The cloud wisp is a hero card with a stock screenshot of a demo wisp.
  - "Add a cloud machine · Soon" is a banner.
  - Next come 3 first steps, computer cards, published-app cards, and 7 "What your grid can do" tiles.
  - Height is 1 680 px at 1280 and about 3 000 css px (3.5 screens) on a phone.
  - **Shared tasks and API keys appear nowhere**, except as tiles that link to the root of the cloud wisp.
- **Account:** good already. Devices, sign-in methods, sign out, delete.
- **Error and offline pages:** a title, one line and a Home button.

### 1. Home: one "Your machines" list, Open on the row, the rest in ⋯

**Where:** `/` signed in (`apps/grid/src/pages/home.rs`: `cloud_block`, `computer_card`).
**Today:** `today/home-full-chromium-1280-light.png`, `today/home-full-webkit-390-light.png`, `today/home-running-chromium-1280-dark.png`.

**Problem.** The thing people come here for is "open my wisp, or one of my computers". It is split in two:
- **Cloud wisp:** a hero card, half of it a stock screenshot of a *demo* wisp. It isn't theirs. On a phone it pushes the computers below the fold, and it loads blank for a moment.
- **Computers:** separate cards. Each shows its full address in a copy field and a greyed Open, but gives no reason it's offline beyond "Offline".

Address, machine type and next schedule show on every visit, though they're rarely needed.

**Change.** One list, **Your machines**, with the cloud wisp first and each computer below it.
- **One row each:** icon · name · a status line in words · **Open** (primary when it can open) · **⋯**.
  - Cloud wisp: "Running · 2 tasks working, 1 needs you · sleeps when idle".
  - Computer: "Offline · last seen 2 h ago", or "never connected · How to connect".
- **The ⋯ menu holds the rest:** copy address, Sleep now, Settings → Agents, API keys, next schedule, Remove (computers).
- **Drop the stock screenshot** from Home. It stays on the landing.
- **On a phone:** offline rows hide the disabled Open; the whole row opens the offline page (#7).

**Mock:** `01-home-1280-light.png`, `01-home-1280-dark.png`, `01-home-390-light.png`, `01-home-390-dark.png`.

**Who does it so:**
- **GitHub Codespaces:** "Your codespaces" is one list of active and stopped codespaces, each opened from its row ([docs](https://docs.github.com/en/codespaces/developing-in-a-codespace/opening-an-existing-codespace)).
- **Tailscale:** Machines is one list with connected / last-seen per row; actions sit behind each row's menu ([filters](https://tailscale.com/kb/1176/filters), [export](https://tailscale.com/kb/1228/export-device-list)).
- **Coder:** workspaces are a filtered list you start, open and stop from ([workspace management](https://coder.com/docs/user-guides/workspace-management.md)).
- **Fly.io:** shipped a mobile-friendly Machines list in 2026 ([changelog](https://fly.io/changelog.md)).

**Impact:** high. The main task is one click, on screen one at every width. Home drops from about 3.5 phone screens to about 1.
**Effort:** M. It's a rewrite of the home template plus a ⋯ menu (`<details>` works without JS, like the existing `add` disclosure). The "2 tasks working, 1 needs you" text needs the counts from the box's `/api/status`, which hostd already polls. Without it, "Running · started 12 min ago" still works.

### 2. Replace the 7 marketing tiles and the 3 steps with one Getting-started checklist

**Where:** `pages/home_tiles.rs` (`offered_tiles`, `reach_tiles`) and the 1·2·3 steps.
**Today:** `today/home-full-chromium-1280-light.png`, the lower half.

**Problem.** "What your grid can do" is 7 pitch tiles on a dashboard. They repeat each other:
- "Sign in to an agent" is both step 2 and a tile.
- "Add a computer" is both a tile and the dashed card.

Six of them link to `/go`, which is just the wisp's root (#3). They stay for ever, even after everything is done.

**Change.**
- **One slim checklist row:** "1 of 3 done · Next: sign in to an agent · Continue · ×".
  - The steps are open your cloud wisp, sign in to an agent, run a task.
  - Each one ticks itself from what the grid already knows, the way the tiles' "✓ 2 added" does today.
  - It hides once done, or once dismissed.
- **The other ideas stay reachable** from a "What else can I do?" link in the checklist and in the header's account menu: phone, publish, share, schedule, API keys, computers. Same text, one click away.

**Mock:** the bottom of `01-home-*.png`.

**Who does it so:**
- **Tailscale:** first run is a single "Let's add your first device" step, not a feature tour ([quickstart](https://tailscale.com/kb/1346/start)).
- **Nielsen:** progressive disclosure keeps advanced options one request away ([source](https://jakobnielsenphd.substack.com/p/progressive-disclosure)). The known risk is guessing the common path wrong. These three steps are the ones the landing itself promises ("Three minutes from here to your first task").

**Impact:** high on clarity: about 9 cards become 1 row. **Effort:** S.

### 3. Every Grid link lands on the exact place in the wisp, not its root

**Where:** every `→ /go` on Home: Schedule a task, Sign in to an agent, Publish from My Stuff, Pick a task, Make a key.
**Today:** each opens the wisp's home screen. `/go` already accepts `?path=` (`edge_handoff.rs`), and the wisp's URL already encodes overlays (`packages/client/src/nav-url.ts`).

**Change.** Each link passes the exact intent, e.g. `/go?path=/?o=settings:agents` and `/go?path=/?o=settings:cloud.keys`. The exact keys come from the settings plugin's overlay ids. "Pick a task" opens the list with Share… explained in a one-time hint.

**Who does it so:** Vercel's 2026 navigation lets a team page jump straight to the same page of one project, "in one click" ([changelog](https://vercel.com/changelog/dashboard-navigation-redesign-rollout)).

**Impact:** high. Today "Make a key" lands on "What should wisp do next?" with no key in sight (`today/inwisp-1280.png`). **Effort:** S. It's query strings plus one table of intent ids, and it applies to the ⋯ items of #1 too.

### 4. One "+ Add" menu instead of three add surfaces and the "Soon" banner

**Where:**
- the "Add a cloud machine · Soon" banner inside the cloud card;
- the dashed "Add a computer" card;
- the "Reach your own computers → Add a computer" tile.

**Today:** `today/home-full-chromium-1280-light.png`, `today/addcomputer-1280.png`, `today/addmachine-1280.png`.

**Problem.** A permanent banner sells something you can't have yet ("Soon"), on every visit, in the most valuable spot. Adding a computer has two entry points.

**Change.** One **+ Add** button beside "Your machines". It opens a menu:
- **A computer of yours:** opens the existing terminal / app instructions, unchanged.
- **Another cloud machine · Waitlist:** opens the existing waitlist dialog, unchanged.

With no computers yet, the list's empty state links the same instructions.

**Mock:** `04-add-menu-1280-light.png`, `04-add-menu-390-light.png` (+ dark).

**Who does it so:** Tailscale's Machines page has one **Add device** that branches by OS ([add a device](https://tailscale.com/docs/features/access-control/device-management/how-to/set-up)). Railway keeps creation in one place and moved navigation out of the way into a sidebar ([changelog](https://railway.com/changelog/2026-03-06-domains-ui-layout)).

**Impact:** medium: fewer things showing, nothing lost. **Effort:** S. Both flows exist; only the entry point moves.

### 5. List your shared tasks next to published apps ("Links"), with copy and revoke

**Where:** Home has **Published apps**, but shared tasks (`/s/<id>`) appear nowhere on the Grid. The only trace is a "Share a task → Pick a task" tile. The API is there: `GET /api/shares`, `PATCH`, `DELETE /api/shares/<id>`, with views and access per share.

**Problem.** A person can't see what they've made public from this account, how often it was opened, or take it down without finding the task in the wisp.

**Change.** Rename **Published apps** to **Links**, with two tabs: **Apps · Shared tasks**.
- Each row shows title · who can open it (anyone / people / teams / passkey) · views · updated, plus **Copy link** and ⋯.
- The ⋯ menu holds open, change access, expiry, and revoke / unpublish.
- The tabs only show when both kinds exist.

**Mock:** the "Links" block in `01-home-*.png`.

**Who does it so:** Stripe and Vercel list every credential or deployment an account made, each revocable from its row ([Stripe keys](https://docs.stripe.com/keys)). Public links are the same kind of exposure.

**Impact:** high for trust and safety. **Effort:** M. The session needs a reach to the shares API (`trust.rs`: `Session` → a `GridPublish`-like read/revoke), plus one list template.

### 6. API keys on Account (list, make once, revoke), not only inside the wisp

**Where:** today the only route is the tile "Settings → Cloud → API keys", which links to the wisp's root. Keys are an account credential, but the Grid's own Account page doesn't show them.

**Change.** An **API keys** section on Account, in the left nav, between devices and sign-in:
- **+ New key** (a name) shows the key **once**, with Copy.
- The list shows name · last 4 · created · last used · Revoke.
- It works while the box sleeps, as `/_grid/keys` does today.

**Mock:** `06-keys-1280-light.png`, `06-keys-390-light.png` (+ dark).

**Who does it so:** Stripe shows a live secret key only once and lets you rotate or delete it from the list ([keys](https://docs.stripe.com/keys)).

**Impact:** medium: the scripts path becomes findable. **Effort:** M. `trust.rs` gives `Session` no keys reach today (`allow: GridPages, GridRoutePage`). It needs a session + CSRF reach for keys at the root origin. That is a trust-table change, so it gets its test row and an ADR note.

### 7. Offline and error pages that wait, explain and offer a next step

**Where:** `<name>--<handle>` when offline (`today/computer-offline-chromium-1280-light.png`), plus "Nothing here", "Nobody here" and "Device connected" (`today/notfound-webkit-1280-dark.png`, `today/activate-done.png`). Each is a title, one line and **Home**, with no signed-in header.

**Change.**
- **Offline computer:**
  - show last seen;
  - show "Waiting for it… this page opens it as soon as it connects", using the account page's existing event stream for online/offline;
  - primary **Open your cloud wisp instead**, secondary **Home**;
  - a folded "On that computer?" with `wisp computer on`.
- **Device connected:** "MacBook Pro can use your wisp now", with **Go to Home**, where the device now shows.
- **All message pages:** the signed-in header when there is a session.

**Mock:** `05-offline-1280-light.png`, `05-offline-390-light.png` (+ dark).

**Who does it so:** Codespaces sends you back to the list to start a stopped codespace when one won't open ([troubleshooting](https://docs.github.com/en/codespaces/troubleshooting/troubleshooting-your-connection-to-github-codespaces)). Tailscale shows last seen for every device ([filters](https://tailscale.com/kb/1176/filters)).

**Impact:** medium. A dead end becomes a wait that finishes by itself. **Effort:** S. The waiting is a small script on the existing SSE.

### 8. Share page: a primary action that works without wisp installed

**Where:** `/s/<id>` (`pages/hub.rs`; `today/share-chromium-1280-light.png`, `today/share-webkit-1280-dark.png`).

**Problem.** The only button is **Open in wisp** (`wisp://open/<id>`). On a phone or a computer without wisp it does nothing, silently. The fallback is a CLI line. The page has no signed-in header, so a Grid user isn't offered their cloud wisp. The section headings sit tight on monospace blocks.

**Change.**
- **Primary action:**
  - signed in to this Grid: **Run it in your cloud wisp** (`/go?path=` the import);
  - otherwise: **Open in wisp on this computer**, with "No wisp? Get wisp" below.
- **Context line on top:** who shared it, the version, and the access ("anyone with the link").
- **Body:** prose for the ask and the answer, monospace only for files.

**Mock:** `07-share-1280-light.png`, `07-share-390-light.png` (+ dark).

**Who does it so:** Cursor's background agents run from any browser at cursor.com/agents, with no IDE required ([TechCrunch](https://techcrunch.com/2025/06/30/cursor-launches-a-web-app-to-manage-ai-coding-agents/), [docs](https://docs.cursor.com/background-agent/web-and-mobile)). Codespaces offers "Open in browser" beside the desktop editor ([docs](https://docs.github.com/en/codespaces/developing-in-a-codespace/opening-an-existing-codespace)).

**Impact:** medium. Shares are the Grid's growth loop, and today the button fails for most first-time visitors. **Effort:** S.

### 9. Inside the cloud wisp: a way back to the Grid, and no "put this on a Grid" tip

**Where:** the cloud wisp at `<handle>.<domain>` (`today/inwisp-1280.png`, `today/go-open-chromium-390-light.png`).

**Problem.**
1. Once you open your cloud wisp, nothing leads back to the Grid (computers, keys, links, account) except the browser's Back button.
2. **A bug:** the home tips show **"Reach this wisp from anywhere: put this computer on a wisp Grid · Set up"** inside a Grid box, which already is one.

**Change.**
- In the account menu of a wisp served by a Grid (`WISP_GRID_URL` is set by hostd), add **wisp Grid ↗** (Home) and **Your computers**.
- Hide the "Reach this wisp from anywhere" tip when `WISP_GRID_URL` is set.

**Who does it so:** Coder lets you "view status and switch between workspaces from the Coder dashboard" ([docs](https://coder.com/docs/ai-coder/coder-dashboard)), and the dashboard stays one click away from each one.

**Impact:** medium. **Effort:** S: one menu entry and one condition on a tip (shell-home i18n key "Reach this wisp from anywhere").

### 10. Sign-in: the last-used provider on top, and `/signin` jumps to it

**Where:** the landing (`/`, and `/signin`, which renders the same long page; `today/landing-chromium-1280-light.png`, `today/landing-full-chromium-390-light.png` is about 5 500 css px tall on a phone).

**Problem.** A returning person whose session expired lands on the full pitch. The page doesn't remember which of GitHub / Google / OIDC they used, so the wrong one creates a second account. `accounts.signIn` never matches by email, by design.

**Change.**
- Remember the last provider in a first-party cookie (no PII; the provider id only). Put it first with a **Last used** tag.
- `/signin`, and the header's **Sign in**, scroll to and focus the provider buttons.
- The pitch below stays as is.

**Mock:** `09-signin-1280-light.png`, `09-signin-390-light.png` (+ dark).

**Who does it so:** Vercel and Railway sign-in pages are a short provider list. I didn't find a cited source for the "Last used" tag; it's an observed industry convention (Linear, Vercel, Stripe), so treat that part as unverified.

**Impact:** low–medium. It prevents duplicate accounts, which today can only be fixed by the operator. **Effort:** S.

### 11. Account: the danger zone folded, devices labelled by kind

**Where:** `/account` (`today/account-full-chromium-1280-light.png`, `today/account-chromium-390-dark.png`).

**Problem.** Small. "Signed-in devices" reads "On the grid as MacBook Pro · added … · last used …", which wraps to 3 lines on a phone. It doesn't say phone vs computer. "Delete your account" sits fully expanded with its input on every visit.

**Change.**
- Label the kind: Computer / Phone app / Desktop app.
- Keep Remove.
- Fold **Delete your account** into a closed "Danger zone" disclosure at the bottom, keeping its typed-handle confirm.

**Who does it so:** GitHub's repository settings keep irreversible actions in a separate "Danger Zone" at the bottom. That's from general knowledge, not verified in a source above. Nielsen describes the confidence that comes from not being able to trigger catastrophe by accident ([source](https://jakobnielsenphd.substack.com/p/progressive-disclosure)).

**Impact:** low. **Effort:** S.

## Notes for whoever builds it

- **What the mocks are:** DOM injections on the real pages. Spacing follows the Grid's existing tokens, but the icons are emoji placeholders. Per D-0056, the owner picks before anything is built.
- **Order:** #1, #2 and #4 are one Home rewrite and should land together. #3 is a prerequisite for the ⋯ items to be useful. #5 and #6 each touch `trust.rs` (a `Session` reach), so each needs a trust-table test row.
- **Seen in passing, not proposals:**
  - `/activate?code=<garbage>` puts the raw param, upper-cased, into the input (e.g. "UNDEFINED").
  - On a cold load, Home's hero screenshot paints as a blank white box before the webp arrives. #1 removes it.
- **Servers:** every server started for this (the dev grid on :8391, its box, the :8398 proxy) was stopped. The scratch data is in `/tmp/uxgrid-data`.
