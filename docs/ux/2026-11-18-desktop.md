# wisp v2 desktop: fewer options showing

Gucci (UI/UX), 2026-11-18. Proposals only: no repo files changed.

**What I looked at.** The v2 dev app at http://localhost:5180 (worktree `wisp-8fb64ec939b0`), read only, with its real data
(1 For later, 31 Done). Chrome (channel `chrome`) and WebKit, 1280 and 1440, light and dark: 24 matrix shots plus
state shots (menus, panel tabs, hover), in `/tmp/qa-keep/ux-desktop/shots/`. Mocks: `/tmp/qa-keep/ux-desktop/mock.html`
(open with `?dark` for dark), rendered per proposal as `mock-P*-light.png` / `mock-P*-dark.png`. They use v1 tokens and
v1 type sizes only.

**Not seen.** No task in this data is running, has a diff, a PR or tool-call activity. So the running row, live
transcript, queued follow-ups, Stop, a filled Changes or PR tab, and the transcript's tool-call collapse are judged
from markup and the empty states. Proposal 12 depends on this.

**Side effect, undone.** Clicking the launcher's Worktree chip during probing flipped the saved default to *In place*.
I flipped it back and checked it in a fresh browser: it shows *Worktree* again.

**The rule I applied.** Show what this moment needs. A feature that's off lives in one place (`+`, `⋯`, a submenu, `/`).
A feature that's on shows as a chip you can clear. Every feature stays reachable from a menu, ⌘K and a key. Nothing
moves on hover: hover actions take the box of what they replace.

## 1. A question stays above the reply box: high · S

- **Where.** Task page, a turn that ends in *Needs your call*. `shots/panel-chrome-1280-light.png`: at 1280 with the
  panel open, options 1–3 sit under the reply box. You can't see them without scrolling.
- **Problem.** The one thing that needs the person is covered. My standards say a question, approval or Send is never
  covered by anything. v1 settled this (`design/ux.md`): answers stick above the reply box.
- **Change.** When the latest turn ends in a question, its card is `position: sticky; bottom: <reply box height + gap>`
  inside the transcript scroller. It sits above the reply box and never under it. The reply box placeholder reads
  *Or answer in your own words…*, which replaces the separate *Answer in my own words* chip (one action, one name).
  Keys 1–9 pick an option while the reply box is empty. Mock: `mock-P7-*.png`.
- **Who.** v1 wisp (`design/ux.md`). Claude Code's own AskUserQuestion pins options at the prompt. Devin and Orca flag
  "waiting on you" first (Orca's agent dashboard, onorca.dev).

## 2. Task row: 2 lines, machine only when remote, hover actions in the time slot: high · S

- **Where.** Task bar, `shots/home-chrome-1440-light.png`, `shots/task-chrome-1440-light.png`.
- **Problem.** Each row has 3 lines: title, last answer line, then *harness · model · This computer*. *This computer*
  is on every row and says nothing when everything runs here. Rows are about 60px, so 12 fit at 900px tall. The only
  hover control is *Later*, and Done, Archive and More need a right-click.
- **Change.**
  - Line 1 is the title and the time.
  - Line 2 is the harness logo plus the last line of the answer. With no answer it reads harness · model. With a
    question it reads the question.
  - The machine name shows only when the task isn't on this computer (*gpu-box · Running tests…*).
  - On hover and on keyboard focus, the 74px time slot swaps to three 24px icon buttons: Later, Done (Reopen when
    done) and ⋯. Each has `aria-label` and `title`. The swap uses opacity in a fixed-width box, so the title never
    reflows.
  - Rows drop to about 44px, so about 18 fit.
  - Mock: `mock-P2-*.png`.
- **Who.** Linear: two-line rows, actions by right-click and keys (linear.app/docs/inbox). Zed's thread list: archive
  on hover (zed.dev/docs/ai/agent-panel). Claude Code desktop and web: archive and delete in a hover ⋯
  (code.claude.com/docs/en/desktop). cmux tabs show branch, PR and the latest notification text, not the host
  (github.com/manaflow-ai/cmux).

## 3. Launcher and reply box: 11 controls to 5, one `+`: high · M

- **Where.** New task launcher, `shots/00-home-1440-light.png`, `shots/20-launcher-*.png`. Reply box,
  `shots/10-task-1440-light.png`.
- **Problem.**
  - The launcher footer shows 11 controls: attach, where (an unlabelled ▭), mode, harness, model, an unlabelled `+`
    (Compare), Delegate, Goal, Worktree, Start later and Send.
  - Under it is a second row: *Recipes · Prompts you send again and again, one click away · + New · Issue*.
  - *Where* and *Worktree* are two chips for one question (where and how it runs).
  - The Home tip says *Click vs in the launcher*, but the control is `+`.
  - The reply box repeats the set as unlabelled icons (harness logo, Delegate, Goal), so it reads differently from the
    launcher.
- **Change.** One footer for both boxes, left to right:
  - `+` opens a menu with Attach files (⌘U), Start from an issue…, Recipes ›, Goal…, Delegate…, Compare with
    another agent… and Start later….
  - Mode chip.
  - Harness · model chip.
  - Where chip: *This computer · Worktree*, *Sandbox* or *gpu-box · In place*. It merges Where and Worktree into one
    menu with two sections.
  - Send.
  - A feature turned on (Goal, Delegate, Compare, Start later) shows as a chip with ✕ after the Where chip
    (*◎ Goal: tests pass ✕*). It takes room only while it's on.
  - The Recipes row goes. Recipes stay in `+` and under `/`. The placeholder hints `@ files · / recipes and commands`.
  - Drag-and-drop and paste still attach.
  - The reply box uses the same footer without the project picker. The harness chip shows the logo plus the model
    name, not a bare logo.
  - Spells: keep every `launcher.*` part name and map the `+` menu items to the same parts, so no spell breaks.
  - Mock: `mock-P1-*.png`.
- **Who.** Claude Code desktop: one `+` button for attachments, skills, slash commands, connectors and plugins.
  Environment, folder, worktree, mode and model sit as chips (code.claude.com/docs/en/desktop). Codex app: the Add
  menu holds files, plan mode and *Set a goal* (learn.chatgpt.com/docs/features). Zed: model chip plus `@` for
  context (zed.dev/docs/ai/agent-panel).

- **Who.** Claude Code desktop: pane icons in the title bar, the rest in a ⋮ overflow, Changes as a `+12 −1` card

## 5. Side panel: only tabs with content, with counts; open on what's newest: high · M

- **Where.** Right panel, `shots/12-panel-1440-light.png`, `shots/18-panel-*.png`.
- **Problem.**
  - All five tabs always show (Changes, PR, Shell, Preview, Thread).
  - The panel opens on Changes even when it's *No changes yet*. PR says *This task has no pull request.*
  - A *This computer* bar repeats under every tab.

  - Mock: `mock-P6-*.png`.
- **Who.** Claude Code desktop: a Changes card `+12 −1`, panes opened from icons, the rest in ⋮. Claude Code web:
