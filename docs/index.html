Why Wisp Agents

The new way to build with agents

Coding agents now write much of the code. The hard part moved: keeping several of them busy, checking their work, and knowing later why a line is there. Wisp Agents is built for that part.

01

Your agents, your plans

Wisp Agents runs the real Claude Code, Codex and the others, signed in with your own accounts. No new model, no markup, no lock-in.

02

Many at once, nothing collides

Each task gets its own git worktree. Run several at once, on this computer, your other ones or the cloud, and ship each as its own pull request.

03

Done means done

Give a task a goal and judges on other harnesses. It keeps going until they agree, or tells you why it can’t.

04

Code that remembers why

Every task is a file in your repo. wisp blame shows which task wrote a line and what it was asked. Rerun it, resume it, share it.

1 · Declare

Your AI dev team, as codeNew

Agents, crew members, machines, skills, MCP servers, rules and workflows live in your repo’s .wisp/ folder. Review a change to your team like any other change. Share it with a link.

  • Variables, references and modules, like infrastructure as code.
  • wisp plan shows what will change; wisp apply makes it so.
  • Skills, AGENTS.md notes and MCP servers shared with the whole team.

Build a software factory as code →

Set up a team
  1. Open the Org page (its button is at the bottom of the rail on the left) and choose Add member: a reviewer, a fixer, a nightly bot.
  2. Settings (⌘K → Settings) → Setup → Make the formula writes your whole setup as a file to commit.
  3. Paste a formula in the same pane to import one: you see what it would change first.
  1. Open the Crew tab to see your members and add one.
  2. Tap a member’s story under the Tasks bar to see what they’re doing, and reply.
  3. Writing the formula itself is easier on a computer: the Desktop app or the CLI.
  1. wisp tui, then g c for the crew view.
  2. n adds a member, a gives one a job, c checks in.
  3. Any CLI command runs from the reply box: /crew create --name Ada.
# .wisp/wisp.yml
wisp: 1
agents:
  reviewer: { harness: codex, mode: plan }
  fixer:    { harness: claude, model: opus }

wisp init   # a .wisp/ folder in this repo
wisp plan   # what applying it would change
wisp apply -f .wisp/wisp.yml

2 · Run

Every harness, any machine, from anywhere

Start a task in one line. Wisp Agents runs the agent in its own worktree, streams what it does, and hands back a short report with the diff and the tests. The full transcript is always one click away.

  • Follow up, queue the next step, or ask on the side with btw without stopping it.
  • Compare two agents on the same task, or try it two ways on one.
  • Run it here, on your other computers over SSH, or in Wisp Agents Cloud.

Run a task and follow up →

Start and ship a task
  1. Press N for New task, pick the agent and model in its footer, type, Enter.
  2. Answer its questions on the task page; reply below to follow up. ] opens the side panel: Changes, PR, Shell, Preview.
  3. Ship (S) commits, pushes and opens the pull request.

In the browser it’s the same window, menus and keys.

  1. In Tasks, tap New task, write what you want, send.
  2. Answer its questions in the task; the reply bar follows up. Swipe a row right to mark it done.
  3. ⋯ (iPhone) or ⋮ (Android) → Ship it… opens the pull request.
  1. wisp tui, n for a new task, Enter to send.
  2. 1–9 answers a question; y a n allow a tool.
  3. /ship ship opens the pull request; d shows the diff.
wisp "fix the flaky reconnect test"   # runs in its own worktree
wisp "add rate limiting to /login" --agent codex --effort high
wisp "audit the auth flow" --compare claude,codex
wisp attach last   # follow it live; reply after
wisp ship <id>   # commit, push, open the PR

3 · Track

Know why every line existsNew

A repo built by agents should remember how it was built. Wisp Agents keeps each task in .wisp/tasks: what was asked, from which commit, what the agent said, the code it wrote.

  • wisp blame on a line, a file or a pull request gives the task and its ask.
  • wisp resume picks last month’s task up on today’s code.
  • Tasks you ran in a harness outside Wisp Agents come in with wisp adopt.

Track your agents’ work beside your code →

Find out why
  1. ⌘K → Repo history: what agents did in this repo, from everyone who worked on it.
  2. Open a task to read what was asked and its report; Resume carries it on, on today’s code.
  3. Keep a task in the repo with Track in its ⋯ menu.
  1. Open a task to read what was asked, its turns and its report.
  2. ⋯ / ⋮ → Rerun… asks the same again; Keep and copy › forks or shares it.
  3. The repo’s full history is in the Desktop app, the TUI and the CLI.
  1. wisp tui, then g h for the repo history view.
  2. Enter opens a task; / searches.
  3. A task’s page says what it was asked and from which commit.
wisp blame src/sync/peers.ts:118   # the task that wrote it, and what it was asked
wisp blame '#812'   # the tasks behind a pull request
wisp log src/sync   # the tasks that touched it, newest first
wisp resume <id>   # carry on, on today’s code
wisp adopt --all --since 7d   # sessions you ran outside wisp

Speed is a feature

Fast enough to forget it’s there

One Rust binary runs the server, the CLI, the TUI and the built-in plugins; a small Solid app sits on top. Speed budgets fail the build, so they stay met.

55 msfrom a cold start to the first answer, with 5,000 tasks
0.95 msto read the first page of a 5,000-task list
103 msfrom an agent’s step reaching every connected app (p99), 10 tasks running
102 MBof memory at rest, holding 5,000 tasks

Measured on 19 November 2026 on an Apple M2 (macOS 15.6) with the repo’s spikes/server-budgets: wisp serve in its release build on 5,000 seeded tasks, fake agents, no network; each time the median of 5 rounds (cold start: 5 restarts a round; the stream: 4 clients, 2,400 steps). The same budgets gate every pull request on Linux, where the numbers are higher.

Wisp Agents Cloud & Grid

Agents that keep working when your laptop sleeps

Wisp Agents Cloud gives you your own instance on a server, signed in with GitHub or Google. Put your own computers on it too, and reach all of them from any browser or your phone. No SSH, no open ports. Or run a Grid on your own server for your team.

About Wisp Agents Cloud

Reach this computer from anywhere
  1. Settings → Machines → Reach this computer from anywhere → Sign in and add it (or Home’s tip → Set up).
  2. Sign in with GitHub or Google.
  3. Open your grid address from any browser or phone.
  1. Open the Computers tab.
  2. Continue with GitHub or Continue with Google.
  3. Your cloud instance and the computers on it show there; tap one to open its tasks.
  1. g m for machines; c connects one.
  2. From the reply box: /grid-client signin --add-computer.
wisp cloud signin   # Wisp Agents Cloud, or: wisp cloud signin <your grid>
wisp computer on   # this computer on the grid
wisp ls --on cloud
wisp grid serve   # run a Grid on your own server

Questions

Frequently asked

Is Wisp Agents free?

Yes. Wisp Agents is open source under the MIT license and runs on your own computers. You use the coding agents you already have, on your own plans and keys, so Wisp Agents adds nothing to your bill. Wisp Agents Cloud, a hosted instance on a server, is optional.

Which coding agents does Wisp Agents work with?

Claude Code, Codex, Cursor CLI, opencode, GitHub Copilot CLI, Grok Build and Antigravity. Wisp Agents runs the real CLIs you already installed and signed in to, so each agent keeps its own models, tools and settings.

Does my code leave my computer?

No. Wisp Agents runs on your machines. Your prompts and code go only to the agents you use, under your own accounts, as they would without Wisp Agents. Wisp Agents sends anonymous usage counts you can turn off, never your code or prompts.

Do I need an API key?

No. If you already use Claude Code or Codex with a subscription, Wisp Agents uses that same sign-in. API keys work too, for agents that take them.

Can I use it from the terminal?

Yes. Everything the app does, the CLI does (wisp "fix the flaky test", wisp ls, wisp ship), and wisp tui is a full terminal UI. After a command fails, wisp "check the error above" hands the agent what just happened in that terminal. Your agents can drive Wisp Agents too, through its MCP server.

Is there a phone app?

The phone apps for iPhone and Android are coming. Join the waitlist on the Get the app page and we email you once, when yours is out. Today you can already use Wisp Agents from your phone’s browser, from Wisp Agents Cloud or a computer you put on the Grid.

Does it run on Windows and Linux?

Yes. The desktop app runs on macOS, Windows and Linux, and the command line installs with npm on macOS, Windows and Linux, x64 and Arm (Node.js 18 or later).

What does “as code” mean here?

Your agents, crew, machines, skills, MCP servers and workflows can live as files in your repo’s .wisp/ folder. You review them in a pull request, apply them with wisp apply, and every task the agents ran is kept next to the code it wrote.
