Each task works in a **worktree**: its own branch in its own folder, made from your repo. Ten agents can work at once
and never collide, and your own checkout stays as you left it. When the work is good, wisp commits it, pushes it and
opens the pull request.

## Worktree or in place

New tasks get a worktree by default. To work in the project folder itself:

<Tabs syncKey="way">
<TabItem label="App">
In **New task**, click the chip that says **This computer · Worktree** and switch it to work in place. The choice is
kept for your next tasks. Settings → General → **Worktree per task** sets the default.
</TabItem>
<TabItem label="TUI">
Press **g** then **,** for settings and find `worktrees.worktree`, or send `/settings set --key worktrees.worktree --value off`.
</TabItem>
<TabItem label="CLI">
```sh
wisp "fix the typo in the README" --no-worktree
wisp settings set worktrees.worktree off     # the default for every new task
```
</TabItem>
</Tabs>

A project can say how its worktrees work: commands to run in a new one, files to copy in, and what to do when a task
is done.

```yaml
projects:
  api:
    path: https://github.com/acme/api   # or the folder's absolute path
    setup: ["npm ci"]
    worktree:
      include: [".env"]          # untracked files copied into each worktree
      onDone: remove-clean       # ask | remove-clean | keep
      cleanupDays: 7
      fixConflicts: true         # an agent resolves PR conflicts by itself
```

The first time a repo asks to run its own setup, wisp holds the turn and asks you
(see [A held turn](../run-and-follow-up/#a-held-turn)).

## Read the changes

<Tabs syncKey="way">
<TabItem label="App">
Open the side panel (**]**) and its **Changes** tab: every file the task changed, with `+` and `−` counts against
the base branch. Comments you leave on lines go to the agent when you send them.
</TabItem>
<TabItem label="TUI">
With the task open, press **d** for the changes pane. Press **d** again to close it.
</TabItem>
<TabItem label="CLI">
```sh
wisp show <id>                          # the answer, with its diff
wisp ship view --session <id>           # each repo's branch, its changes and what would ship
```
</TabItem>
</Tabs>

## Ship it

Shipping commits what's uncommitted, pushes the branch and opens a pull request (or pushes to the one it has).

<Tabs syncKey="way">
<TabItem label="App">
Press **Ship** at the top of the task (**S**). Check the title and description (**Write it with …** has the agent
write them), tick **Open as a draft** if you want, then **Commit & open PR**.
</TabItem>
<TabItem label="TUI">
With the task open, press **i** and send:

```text
/ship ship --session <id> --title "Add a rate limit to /login"
```
</TabItem>
<TabItem label="CLI">
```sh
wisp ship <id>            # commit, push, open the PR
wisp ship <id> --draft
```
</TabItem>
</Tabs>

## Checks, reviews and conflicts

The **PR** tab follows the pull request: its checks, its reviews and comments, and whether it can merge. wisp
checks GitHub every minute.

- **A failing check:** **Ask to fix** puts the check's name and the end of its log in the reply box. Read it, then
  send.
- **A review comment:** it lands in the reply box the same way, to send to the agent.
- **Conflicts with the base branch:** **Fix conflicts** sends the task a follow-up to merge its base in and push.
  With Settings → General → **Auto-fix PR conflicts** on, it does that by itself.

<Tabs syncKey="way">
<TabItem label="App">
Side panel → **PR**. The same buttons show on the PR strip at the top of the task.
</TabItem>
<TabItem label="TUI">
```text
/ship details --session <id>
/ship fix-conflicts --session <id>
```
</TabItem>
<TabItem label="CLI">
```sh
wisp ship details --session <id>        # every PR of the task, checks and reviews included
wisp ship fix-conflicts --session <id>
```
</TabItem>
</Tabs>

## Merge

Merging squash-merges the PR on GitHub, fast-forwards your local base branch, and removes the worktree unless it
holds uncommitted work.

<Tabs syncKey="way">
<TabItem label="App">
**PR** tab → **Merge**, then **Merge PR**. If checks fail or no other harness reviewed it, wisp says so first;
**Merge anyway** goes ahead.
</TabItem>
<TabItem label="TUI">
```text
/ship merge --session <id>
```
</TabItem>
<TabItem label="CLI">
```sh
wisp merge <id>
```
</TabItem>
</Tabs>

## Tidy up

Finished worktrees are cleaned up after a while. A worktree that holds work is never removed without your yes.

<Tabs syncKey="way">
<TabItem label="App">
Settings → Computers → **Worktrees** lists them, with how much room they take. On a task, **⋯** → **Task options**
→ **Keep worktree** keeps it out of the cleanup.
</TabItem>
<TabItem label="TUI">
Send `/worktrees keep --id <id> --keep true`.
</TabItem>
<TabItem label="CLI">
```sh
wisp worktrees view                     # the worktrees on disk
wisp worktrees keep --id <id> --keep true
wisp worktrees sweep                    # tidy idle worktrees now
wisp settings set worktrees.onDone ask  # when a task is done: ask, remove or keep
```
</TabItem>
</Tabs>

Before you merge, you can have another harness read the diff: see [Review by another agent](../review-by-another-agent/).
