wisp runs the Cursor CLI, `cursor-agent`, in the background, one worktree per task, on your own Cursor account.

## What you need

The Cursor CLI. The Cursor editor doesn't include it.

```sh
curl https://cursor.com/install -fsS | bash      # macOS and Linux
```

On Windows, follow [cursor.com/cli](https://cursor.com/cli).

## Sign in

<Tabs syncKey="way">
<TabItem label="App">
Avatar → **Settings** → **Agents** → **Sign in** next to Cursor, then **Open the sign-in page**. Or press **Keys**
and paste a Cursor API key.
</TabItem>
<TabItem label="TUI">
Send `/accounts login start cursor default` and open the link it gives.
</TabItem>
<TabItem label="CLI">
```sh
wisp accounts login start cursor default
wisp accounts login status cursor default
```
Or run `cursor-agent login` yourself, or set `CURSOR_API_KEY`.
</TabItem>
</Tabs>

## Pick it and its model

wisp reads the models from `cursor-agent --list-models`. Cursor has no effort setting.

<Tabs syncKey="way">
<TabItem label="App">
Click the harness chip in the New task footer, pick **Cursor**, then a model.
</TabItem>
<TabItem label="TUI">
Send `/runtime set-agent --agent cursor` to move the open task to Cursor.
</TabItem>
<TabItem label="CLI">
```sh
wisp "rename the config loader" --agent cursor --model <id>
```
</TabItem>
</Tabs>

Modes: **Plan**, **Edits**, **Full auto** (`--mode plan|edits|auto`).

## What's different with Cursor

`cursor-agent` takes no MCP server by flag. So it has no wisp tools in a task: when it needs you, it ends its
answer with a question block, and you answer in the reply box. It can't start other wisp tasks either.

## Open in Cursor

<Tabs syncKey="way">
<TabItem label="App">
The task's **⋯** menu → **Open in Cursor** (key **T**).
</TabItem>
<TabItem label="TUI">
Press **o** in the open task.
</TabItem>
<TabItem label="CLI">
```sh
wisp runtime resume-command <id>
```
</TabItem>
</Tabs>
