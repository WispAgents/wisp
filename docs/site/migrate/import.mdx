Used an earlier wisp (1.x)? Your setup and your task history come with you in one command. It shows its plan first
and changes nothing until you say yes.

## Import

<Tabs syncKey="way">
<TabItem label="Desktop app">
Importing runs in a terminal. Run the CLI command, then open the desktop app: what came in is already there.
</TabItem>
<TabItem label="Phone app">
Importing runs in a terminal on the computer, so it can't be done from the phone. Run the CLI command there,
then open that computer in the phone app: what came in is already there.
</TabItem>
<TabItem label="TUI">
Quit the TUI (**q**), run the CLI command, then `wisp tui` again.
</TabItem>
<TabItem label="CLI">
```sh
wisp import --dry-run              # the plan only
wisp import                        # the plan, then "Import it? [y/N]"
wisp import --yes                  # no question (for scripts)
wisp import /path/to/old/home      # another folder than ~/.wisp
```
Outside a terminal, `wisp import` needs `--yes`.
</TabItem>
</Tabs>

## What comes over

It reads the old home's `config.json` and its `sessions` folder, and brings in:

- **Projects.** A project whose folder isn't on this computer anymore is left out, and the plan says so.
- **Defaults**, as settings: your default harness, model and effort among them.
- **Recipes**, as declared tasks.
- **Automations and schedules**, as triggers.
- **Crew members** and **teams**.
- **Machines** and **connectors**.
- **Task history:** every task with its transcript and its changes per turn. Tasks are history, so they are
  imported, never planned. A task already imported is skipped, so you can run the import again.

The plan shows each change as `wisp apply` would. Notes under it name anything that didn't carry over.

## Secrets

Tokens and keys are never written into a plan. A connector's environment or a channel's token that wisp already
has becomes a `${secret:NAME}` reference. Any other is named in the plan's notes. Set it with:

```sh
wisp secret set NAME       # typed hidden, or piped: echo "$TOKEN" | wisp secret set NAME
```

## What changed

| Before | Now |
| --- | --- |
| Spells | [Plugins](../../concepts/plugins/). A spell isn't imported: [Make wisp your own](../../plugins/make-wisp-your-own/) shows how to rebuild one, or ask an agent to. |
| Settings only in the app | The same settings, plus a formula in your repo (`.wisp/*.wisp.yml`) with `wisp plan` and `wisp apply`. |
| Task history only on your machine | Optionally kept in the repo (`.wisp/`), so the team sees why the code is the way it is. |

Everything you did in the app before is in the same place now, and looks the same.

## Keep your setup in the repo

After importing, write it out as a formula you can review and commit:

```sh
wisp export > .wisp/setup.wisp.yml
```

See [Formulas](../../concepts/formulas/).
