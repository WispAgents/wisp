A **task** is one piece of work you hand to an agent: "fix the flaky login test", "add a dark mode toggle". wisp
gives it its own copy of your repo (a git worktree), runs the agent there, and shows you what it did.

## Start it

<Tabs syncKey="way">
<TabItem label="Desktop app">
Press **New task** (**N** or **⌘L**), pick the project, type what you want, and press **Enter**. The footer under the
box picks:

- **The mode:** *Plan* only reads and proposes. *Edits* changes files and asks before anything else. *Full auto*
  does the whole job without stopping.
- **The agent and model:** Claude Code, Codex, Cursor and the rest, each with its own models and thinking level.
  New task keeps your last pick.
- **Where:** *This computer · Worktree* by default: the task works in its own folder and branch, so your checkout
  stays as it was and several tasks can run at once.

In the browser (`wisp --browser`, or your cloud wisp) it's the same window, menus and keys.

<Shot name="new-task" alt="The New task box with a prompt typed, and its footer: +, the mode, the harness and model, This computer · Worktree, and Send" />
</TabItem>
<TabItem label="Phone app">
Tap **New task** (on iPhone, the compose button at the top right). Pick the project, type what you want, and tap
**Send**. The chips under the box pick the mode, the agent and model, and where it runs, the same as on the desktop.
New task keeps your last pick.
</TabItem>
<TabItem label="TUI">
Run `wisp tui` in your repo. Press **n** for a new task, type, and press **Enter**. **Shift-Tab** cycles the mode
(plan → edits → auto).
</TabItem>
<TabItem label="CLI">
In your repo:

```sh
wisp "fix the flaky login test"
wisp "fix the flaky login test" --agent codex --effort high --mode edits
wisp "fix the flaky login test" --no-worktree      # work in your checkout instead
```
</TabItem>
</Tabs>

## Watch it

While it works you see what it's doing right now. When it's done you get its answer as cards: what changed, the
diff, the tests it ran, screenshots, what you might do next. The full transcript is always one click away.

<Tabs syncKey="way">
<TabItem label="Desktop app">
The task opens beside the list. Its state shows on its row: working, needs you, finished. **J** and **K** move to
the next and previous task. **V** opens the full transcript.

<Shot name="task" alt="A finished task: the agent's report as cards, with what changed, the diff and the tests it ran" />
</TabItem>
<TabItem label="Phone app">
Tap the task in **Tasks** to open it. The list groups tasks by state: *Needs you*, *Working*, and the rest.
**⋯** (iPhone) or **⋮** (Android) in the task's top bar → **Show ›** has the full transcript.
</TabItem>
<TabItem label="TUI">
**Enter** opens the task. **j** and **k** move between its steps, **Space** opens one, **d** shows the diff.
</TabItem>
<TabItem label="CLI">
```sh
wisp ls                 # every task and its state
wisp attach last        # follow the newest one live, with a reply box after
wisp show last          # its latest answer as markdown
```
</TabItem>
</Tabs>

## Follow up

A follow-up sent while the task works interrupts it, or waits its turn if you queue it.

<Tabs syncKey="way">
<TabItem label="Desktop app">
Press **/** to jump to the reply box under the answer, type, and press **Enter**. If the answer suggested
follow-ups, the first shows faded in the box: press **Tab** to use it. Switch **Queue** on to send it after the
current turn.
</TabItem>
<TabItem label="Phone app">
Type in the reply bar at the bottom of the task and tap **Send**. To send it after the current turn, tap the
options chip in the reply bar and switch on **Queue**.
</TabItem>
<TabItem label="TUI">
Press **i**, type, **Enter**. While a turn runs, **Enter** queues it; **Ctrl-S** sends a queued one now.
</TabItem>
<TabItem label="CLI">
```sh
wisp reply last "also cover the logout path"
wisp reply last "then update the changelog" --queue
```
</TabItem>
</Tabs>

## Ship it

Shipping commits the task's changes, pushes its branch and opens a pull request. wisp then follows the PR's checks
and reviews on the task.

<Tabs syncKey="way">
<TabItem label="Desktop app">
**Ship** at the top of the task (**S**). *Write it with …* has the task's agent write the PR title and description
from the diff, following your repo's pull request template. When you're happy, **Done** (**E**).
</TabItem>
<TabItem label="Phone app">
Open **⋯** (iPhone) or **⋮** (Android) in the task's top bar → **Ship it…**. When you're happy, **Mark done** in the same
menu, or swipe the task right in the **Tasks** list.
</TabItem>
<TabItem label="TUI">
With the task open, send `/ship ship`. `/ship merge` squash-merges it.
</TabItem>
<TabItem label="CLI">
```sh
wisp ship <id>          # commit, push, open the PR   (--draft)
wisp merge <id>         # squash-merge it and sync your local base branch
```
</TabItem>
</Tabs>
